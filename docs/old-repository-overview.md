# Old LIMB Repository Overview

## Scope and confidence

This is a high-level, read-only inspection of the separate `LIMB-HT25` repository found alongside the current academic work. The unresolved `<OLD_REPO_PATH>` in the task brief was matched to that repository by its name, year, and contents. This identification should be confirmed by the group.

The inspection considered directory and file names, repository documentation, and selected source comments. It did not run Git, builds, tests, simulations, hardware interfaces, or programs. Accordingly, **implemented** below means that relevant files appear to exist; it does not mean that the subsystem builds or works on the arm.

At inspection time the repository contained approximately 1,038 non-Git files. The largest areas were `src/`, `dmp/`, `designs/`, a separate `LIMB Simulation/`, human-arm data capture, and project documentation.

## Cross-cutting findings

- The intended architecture appears to use an NVIDIA Jetson AGX Orin as the computer-side controller, with distributed ESP32-C3-Zero nodes communicating over CAN; a human-worn sensing cuff communicates over BLE. This is an interpretation of the documentation and must be confirmed against the current hardware.
- The repository contains both a layered host-control path and multiple standalone, experimental, or subsystem-specific scripts. File presence alone does not identify the deployed path.
- CAN is relatively well documented, but documentation explicitly reports recurring bus-off behavior on the physical arm. Protocol consistency and physical-layer health are priority questions.
- Firmware is divided into shoulder, elbow, hand-motor, hand-pressure, and human-lower-arm targets plus shared components. The firmware actually installed on each board is unknown.
- Safety warnings in the legacy repository describe possible unexpected or continued motor movement. The host control layer also contains TODOs for collision avoidance and emergency-stop conditions. Inherited limit claims must therefore be validated rather than trusted.
- Hardware material includes a BOM, PCB/schematic sources, manufacturing exports, CAD, and photographs, but the as-built revision has not been established.
- Research and experimental material is substantial, particularly DMP/trajectory work, EMG, vision, sensor fusion, human motion capture, and simulation. It should remain separate from restoration-critical control until evaluated.

## Migration implication

The useful LIMB work should be selected by subsystem, not copied by directory. A future inventory should record the legacy path, purpose, owner or provenance where known, dependencies, hardware association, apparent duplicates, generated status, safety impact, validation evidence, and proposed AURORA destination. Migration has not started.
